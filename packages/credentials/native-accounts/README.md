# arx-native-accounts

Native Claude Code, Codex, and Antigravity CLI account management for Settings. The package installs the official Claude Agent SDK and the pinned Codex app-server payloads and resolves their platform executables without requiring a global CLI installation. The Antigravity CLI (`agy`) installs outside any package manager and updates itself, so the deployment names its executable with `antigravityExecutable`; without one, Antigravity reports unavailable. The products own credential persistence; the harness never reads their credential files or copies tokens into settings.

`ctx.nativeAccounts.describe()` runs bounded native status probes and returns connection state, supported login modes, and available native model metadata. Email addresses, account identifiers, tokens, raw stdout, and stderr are excluded. Claude model discovery uses the SDK initialization protocol without submitting a prompt; Codex uses `model/list` and follows its pagination. Codex's server filters that list by the signed-in plan and the client's version, so a model reaches the roster only once the pinned Codex release is new enough for it; a stale pin can leave a model the current one serves missing from the roster. Antigravity status and models both come from `agy models`, which needs no model turn: exit code 0 is a signed-in account whose listing lines each name one model by their first token, with the rest of the line as its display name; exit code 1 with `Please sign in to view available models.` on stderr is a signed-out account; any other result reads as unknown, and a listing line that does not start with a model id leaves the account connected without models. Native metadata supplies no inferred context-window capacities.

`begin(provider, mode)` returns an unguessable private attempt id. Only that id can poll, submit a requested code, or cancel the attempt. One attempt per product runs at a time; `maxAttempts` caps active and retained attempts together. Concurrent account-directory requests share one bounded set of probes. Each attempt has a configured deadline and a short terminal-result retention period. Cancellation, expiry, and plugin disposal terminate and await the native process tree. Account listings never contain attempt ids. A reload loses the private capability; the attempt expires automatically.

Claude uses `auth login --claudeai`, relays only an allowlisted HTTPS authorization address, and bridges the pinned CLI's `Paste code here if prompted >` input through a transient Settings field. This supports a browser on another machine while the CLI remains on the host. Codex offers its pinned app-server's browser and device-code modes. For a browser sign-in, the driver reads the return address from the authorization address's `redirect_uri` — always `http`, host `localhost` or `127.0.0.1`, an explicit port — and, in parallel with the browser step, asks the person for the address of the page the browser ended on (attempt input `redirect-url`). A pasted address must match that return address's protocol, host, port, and path and carry a query; only the query is forwarded, to `http://127.0.0.1:<port><path>` on the host (`redirect: manual`), which is the app-server's own callback listener bound to the IPv4 loopback address. A response below 400 ends the relay and the app-server completes the sign-in; a refused or unreachable listener, or a non-matching paste, sets the attempt's `rejected` flag and asks again, until the attempt settles. A successful CLI exit is followed by native Claude subscription status verification; Codex completion must match the started login id. Antigravity uses `agy acp --login`, relays only `accounts.google.com` addresses, and bridges the CLI's `Then paste the authorization code, or the full URL of the page you land on, and press Enter:` prompt through the same transient field; the CLI rejects a wrong code by exiting with code 1, which fails the attempt, and a zero exit must be followed by a signed-in `agy models`. Login does not submit a paid model request.

The native account RPCs are part of the loopback, same-origin configuration plane, including status reads. A browser connected directly to a public VM address cannot use them; an authenticated local tunnel preserves this restriction. Native Codex login enables the native product account and does not create a direct `llm-pi-ai` credential or a main-chat model route. No endpoint logs out a shared native account.

## Configuration

`cwd` selects the native working directory, and `env` overlays the subprocess service's credential-scrubbed environment. `graceMs` controls process-tree teardown, `outputMaxBytes` bounds collected native output, `probeTimeoutMs` bounds account discovery, `loginTimeoutMs` bounds user sign-in, `resultRetentionMs` bounds terminal-result retention, `maxAttempts` caps retained capabilities, and `pollIntervalMs` supplies the browser's progress refresh interval. `antigravityExecutable` is the absolute path of the installed `agy` (the official installer writes `~/.local/bin/agy` on macOS and Linux); a relative path fails at load. Defaults are declared by the plugin schema.

## Model Experience

None, as account status and sign-in are configuration-time interactions with a human, and no status, attempt, or answer reaches a model request or a session log.

#### KV Cache effect

No invalidation; no account state enters a request prefix.

## Known Limitations and Deferred Work

- **Native credentials are the host user's** — the tools store their login under the host's operating-system account, where other installed clients of the same product may share it; this service reads none of it and offers no sign-out.
- **An attempt does not survive a restart** — attempts live in memory, so a host restart or a page reload that loses the attempt id abandons the sign-in until its deadline withdraws the process.
- **Codex browser sign-in returns to the host's loopback** — the Codex app-server serves the sign-in callback at `http://localhost:1455/auth/callback` on the harness host, or `http://localhost:1457/auth/callback` when port 1455 is already taken there. A browser on another machine finishes that sign-in by pasting the address the browser ends on into the attempt's `redirect-url` prompt, or, as the [remote-access guide](../../../docs/user/guide/security.md#remote-access-through-ssh) shows, through a tunnel that forwards both ports; device-code sign-in needs neither.
- **Antigravity has no chat route** — the CLI runs its own tools in every non-interactive mode it documents, so arx lists its models and does not offer them to chat; its terms of service also restrict use alongside products Google does not provide.
- **The Antigravity listing format is unverified** — the signed-out output and the sign-in prompt match Antigravity CLI 1.5.16; the signed-in `agy models` format is not documented, and the one-model-per-line reading has not been checked against a signed-in account. The CLI updates itself on every run, so any of these texts can change without a version change in arx.
- **Running `agy` writes to its own state** — every probe starts the CLI, which creates its data directory under `~/.gemini/antigravity-cli` and may start its background self-update.
- **A connected account configures no route** — listing a tool's models configures nothing; the Claude chat route exists only once the Models page enables it, and a Codex sign-in authorizes the Codex tool, not the library-backed `openai-codex` chat route.
