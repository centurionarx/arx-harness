# GitHub host authorization ownership

The GitHub service accepts an operator-selected credential address, not a credential through a public RPC. Unconfigured startup avoids presenting a secret-collection flow before an operator decides where credentials are held. The existing authorization service owns human interaction and observes the actual credentials record commit; a reference-only write cannot satisfy its success condition. The plugin owns only github/account and replaces its api-key record under the provider lock, checking cancellation before enqueue and inside the exclusive callback. Returning a replacement linearizes the commit decision; cancellation after that decision never triggers a competing rollback.

Keeping the record and reference namespaces separate avoids an apparent successful write hidden by environment precedence. Record reads do not resolve references, and a reference configuration never offers the PAT-writing flow. A provider reporting a nonwritable record remains visibly nonwritable. Masking a human prompt and omitting credentials from public DTOs prevent automatic transcript exposure but do not prevent same-UID store reads; operating-system isolation is an independent prerequisite.

Native fixed-origin fetch avoids an arbitrary URL capability. Ignoring upstream Link URLs prevents pagination from becoming a network selector. Streaming response bounds constrain retained external data, and complete-result bounds independently constrain wrappers and metadata. Allowlisting checked fields excludes external diagnostics and metadata; fixed errors exclude credentials, response bodies, headers, and causes. No retry or 401-triggered deletion competes with credential rotation.

The real Loader tests use actual authorization and a serialized in-memory credential provider. External fetch is the only mocked service. Assembled UI, transport envelopes, transcript proof, published artifacts, aggregate compiler registration, and the repository-level Agent Note remain parent-owned integration obligations; this package-local decision record does not substitute for their acceptance.
