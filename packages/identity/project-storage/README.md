# Project storage

Reference for the `projectStorage` provider and its USER HTTP consumer.

The service checks current identity ownership before reading history, listing metadata, changing titles, removing grouping or deleting a session. MASTER-ADMIN has no content access. Project and workspace ids are generated by the identity service; display names never select filesystem paths.

## Configuration and composition

Load the existing `sessionPersistence` JSONL provider with a private `logRoot`, then this provider. `indexPath`, `logRoot` and `volumeRoot` must be disjoint operator-owned locations. Only one opaque workspace volume belongs in a worker mount; its parent, history root, index, authority journal, identity database and operator keys remain outside the worker.

`pageSize` admits at most 50 headers. `maxPageBytes`, `historyPageBytes`, `appendBytes` and `busyTimeoutMs` are explicit deployment limits; history responses admit at most 128 KiB including their envelope. Index writes use SQLite WAL with FULL synchronization.

The `./http` consumer requires `webIdentityApi` with audience `user` and `webServer`. It reuses the identity request authenticator for Host, Origin, cookie, bearer and CSRF checks. Every mutation requires the same authentication policy as the identity API. Immediately after request authentication, its internal admission helper reuses the existing `allowsProjectAccess` contract before parsing paths or bodies or accessing storage. Detached-principal policy tests do not establish request authority or ownership; the actual carrier and providers still enforce CSRF, ownership and current-authority revalidation. GET, history/export and other reads remain passive. The exact project/workspace creation, title change, grouping removal and session-deletion routes renew only after a successful provider operation. Creation and other surviving resources must still satisfy the storage grant and authoritative ownership before renewal and after its journal/FULL commit; cancellation and publisher admission are checked again before the HTTP receipt. Session deletion qualifies its still-valid actor without reauthorizing or resurrecting the tombstoned resource.

## Ownership and durability

Session registration commits identity ownership before creating lazy persistence metadata. `materialize(authority, id, signal?)` explicitly commits an indexed owned header through the configured provider and revalidates ownership before completion. An admitted provider write finishes; cancellation or lost authority rejects the receipt after that write. The header's cwd comes from the opaque volume manifest. Append success requires the existing persistence provider's fsync and the index's FULL commit. Failure publishes no saved cursor. Recovery uses identity ownership first and rebuilds missing metadata from a matching private log; it never deduces an owner from cwd, a username or a legacy header and never resumes external work.

`executionCreationHeader(authority, id, signal?)` reads the indexed canonical header of an already registered owned session without creating or reading an artifact. It checks the current storage grant and owner before access, revalidates ownership before completion and refuses cancellation. The isolated worker consumes this metadata through its [private creation broker](../../host/isolated-project-runtime/README.md#authority-and-protocol); it does not issue physical source revisions or expose a USER HTTP route.

`workspaceOrder(authority)` returns the user's grouped, owned workspaces in display order; workspaces absent from the stored order follow in creation order. `moveWorkspace(authority, workspaceId, beforeWorkspaceId?)` checks ownership of both workspaces and stores the complete order in the additive `workspace_order` table; existing tables and `user_version` are unchanged. A stored order that is not a JSON array of strings fails both methods with `corrupt project storage workspace order`, and no part of it is applied. The isolated runtime uses both to answer user-level listings and `workspace.insertBefore`. Applying the table to a deployed index is an operator step.

Removing grouping preserves identities, histories and files. Session deletion commits a journal-backed identity tombstone before deleting derived metadata. Restoring an older index cannot authorize a tombstoned session. Physical purge and backup expiration require the operator retention procedure.

Execution metadata comes from one provider snapshot scan per workspace request, followed by an authoritative ownership check for every indexed candidate and final revalidation. Direct execution revision reads use the provider's per-id `readRevision`; full snapshot hydration still validates the complete log between source revisions and finishes any started durable repair before acknowledging. Default lazy logs remain absent until their first append or an explicit owned header commit. `executionAppend`, the worker broker's append, skips leading events that the log already holds with the same content and appends only the rest, so a worker can resend a batch whose append was committed but refused after the commit; a held event that differs fails on the provider's sequence check, as every held batch does through `append`.

## USER HTTP routes

| Route | Result |
| --- | --- |
| GET/POST `/user/projects` | Owned project page; creation accepts a display `name`. |
| GET/POST `/user/projects/{id}/workspaces` | Owned workspace page; creation accepts a display `name`. |
| GET `/user/projects/{id}/sessions` | Session headers, optional `workspaceId` and continuation `cursor`. |
| GET `/user/sessions/{id}/history` | Original raw JSONL page and source-bound opaque continuation. |
| GET `/user/sessions/{id}/export` | Own raw JSONL download; authority is rechecked before each chunk. |
| PATCH/DELETE `/user/sessions/{id}` | Index title change or authoritative session tombstone. |
| DELETE `/user/workspaces/{id}/grouping` | Grouping removal preserving histories and files. |

Raw history/export preserves the own SessionHeader.cwd field and can therefore name the user's own physical volume. Navigation/provision DTOs expose only ids and display names. No incoming cwd/raw path is accepted as authority or as a provisioning target.

The `./contract` export contains browser-safe DTOs and HTTP response parsers. It exports no filesystem location, credential or issued authority.

## Model Experience

### Durable conversation data

#### What the model sees

This package contributes no prompt or tool schema. It retains the existing `SessionEvent` log; the owning session and context plugins decide which persisted events reach a model.

#### Token effect

Zero direct request-token effect.

#### KV Cache effect

History storage preserves the existing event representation and contributes no request-prefix mutation.

## Known Limitations and Deferred Work

- Raw pages require the provider capability `supportsRawArtifactPages`; unsupported backends fail closed rather than falling back to a full raw-log buffer. The JSONL reader bounds retained conversation bytes and decoder stream chunks, rejects changed-revision continuations and validates each containing Zstandard frame before returning its prefix.
- Existing giant Zstandard append frames require reading/decompressing through their checksum while retaining only the page. Later unrequested frames are skipped. The provider config caps its native decoder window; frames requiring a larger window reject instead of silently lifting the bound. Repeated pages/export of a giant frame repeat its checksum work.
- Workspace content access belongs to the isolated runtime endpoint. This provider never reads or writes worker-created files.
- Real mount, UID, VM and network isolation, retention, physical purge and production restore drills require the separately authorized deployment.
