# Agent Note: Native web identity journal and deployment audience

Status: implemented

## Problem

Provider credentials authorize model vendors, not a person using the harness website. Browser reachability rules also cannot identify that person. Administrative account release must not grant access to project content, and an older identity backup must not revive revoked access. HTTP authorization alone leaves shell, filesystem and shared-process access outside that decision.

## Decision

The [web identity definitions](../../../../packages/identity/web-identity/README.md) separate native accounts from [provider credential records](2026-08-13-credential-records-and-authorization-flows.md). Provider-issued RequestAuthority values are immutable, and a copied DTO cannot substitute for an issued authority. Revalidation refuses an older revision and either session expiry. Schema 2 records the idle deadline independently of the immutable absolute deadline; the idle interval is an explicit provider configuration. Admitted carrier mutations request journal-first FULL activity renewal after Host/Origin, credentials and applicable CSRF verification. Passive polling, WebSocket admission and worker progress cannot renew the deadline. A previous schema is refused without an automatic migration. The browser-safe policy predicate expresses USER/ACTIVE/password-established eligibility; carriers still authenticate, revalidate and authorize the exact owner before final dispatch. A shared frozen presentation selects the matching public, administrative or USER composition without authority, tokens or content; recovery entries remain public and incompatible role/audience facts produce no presentation.

Deployment fixes USER or administrative audience and canonical origin, including scheme. Separate HttpOnly audience cookies and a session CSRF verifier serve the browser; explicitly configured non-browser bearer clients reuse the same request authenticator. MASTER_ADMIN manages USER creation/release, status and installed module grants, with no ownership operation, impersonation, role conversion, established-email rewrite or final USER-password assignment. Invitation acceptance establishes the recipient's password independently of administrative release.

The [external journal](../../../../packages/identity/identity-authority-journal/README.md) is canonical authorization authority, including credential verifiers, revisions and owner tombstones. Its fsynced record and current watermark precede the independent [SQLite FULL projection](../../../../packages/identity/web-identity-sqlite/README.md). ACK also awaits execution quiescence. The FIFO writer section releases after FULL projection and before awaited listeners, allowing queued broker owner registrations to reject against committed revisions or tombstones without a dependency cycle. The explicit restore fence follows this order; provider disposal closes admission before draining writes and awaiting quiescence. A projection or quiescence failure withholds success while the committed revocation remains effective. Ownership deletion uses its own awaited event, preserving a valid cookie and auth generation while denying deleted resources and descendants. A single provider timer follows the nearest durable absolute or idle deadline without using polling as activity. Session expiry FULL-projects its own revoked row before an awaited SID event outside the writer queue. A later batch failure still quiesces the committed prefix. Critical expiry or scheduling failure closes admission and attempts disposal invalidation for every account through a shared task that provider shutdown awaits; failed drains remain unconfirmed.

Caller deadlines are checked before session ownership enters the writer and after owner admission before append. Once append begins, the authority completes FULL projection; cancellation cannot erase a committed owner or strand the content index by losing its proof. Transport consumers still withhold the late response.

The current external authority is excluded from rollback snapshot sets. Replay projects current credentials/status/grants/owners/tombstones over an older DB and invalidates historical sessions, recovery links and pending mail. Same-head restoration uses the explicit operator restore fence. A missing journal/watermark is not normal-startup initialization. Hash linking detects corruption, while protection from an operator rewriting the complete authority depends on independently protected storage.

Existing Node scrypt and node:sqlite provide bounded asynchronous password work and local durable decisions without another native dependency. Hash work is limited to two active requests and a bounded pending queue; admission checks abort and current credential/link state again after hashing. Purpose-bound digest tokens and encrypted SQLite outbox state keep raw links out of the journal. The [Resend adapter](../../../../packages/identity/web-identity-resend/README.md) sends only to registered recipients and treats external acceptance separately from delivery.

## Alternatives considered

**Provider login as site login.** Vendor grants identify a provider account, have different credential lifecycles and cannot establish project ownership or a MASTER role. Existing credential/authorization plugins retain their own responsibilities.

**Database-only authority.** A restored DB would also restore old revisions, passwords and link states. The independent current journal retains decisions that an older projection loses. It costs a second durable write and an operator-owned authority recovery procedure.

**Browser-local history or all contents in the identity database.** Browser-local authority loses device-independent continuity; storing complete workspaces and logs in auth SQLite couples account admission to content/tooling. [Control history and isolated workers](2026-10-08-control-history-and-isolated-workers.md) owns the separate hybrid content design.

**Argon2id through a new native package or PostgreSQL for the initial control node.** Both are valid alternatives with additional build/service operations. Native scrypt and local SQLite reuse the measured runtime for this single-control-node implementation. The database choice does not promise scale or measured fastest performance.

**Shared-UID worker directories or implicit MASTER superuser access.** Owner labels cannot stop an untrusted process reading another directory, and administrative content access violates the role restriction. The code therefore supplies no local execution fallback; actual worker/UID/volume/network separation remains an operational prerequisite.

## Consequences

The [keyless Loader fixture](../../../../examples/web-identity/README.md) exercises real issued identity, native hashing/SQLite, journal replay, Node HTTP, cookie/CSRF and quiescence with synthetic secrets and external delivery replacements. Named native-boundary faults verify cancellation, failed projection, TTL/single-use races, late mail acceptance and disposal. These are implementation and protocol proofs, not production TLS, sender delivery, operating-system isolation or disaster-recovery acceptance.

The [browser trust decision](2026-07-28-api-browser-trust-boundary.md), [event-sourced sessions](2026-06-11-event-sourced-sessions.md), [project-session directories](2026-07-24-project-session-directories.md) and provider credential decision remain active: this decision adds account authority without replacing their local transport, event order, persistence/collision or vendor grant rationale. The [deployment proposal](../../proposed/architecture/2026-10-08-native-web-authority-and-owned-control-plane.md) owns the remaining integrated and operational approvals, including protected control storage, isolated supervision, quotas, retention, restore objectives and real email. Local crash durability does not imply survival of authority-disk loss.
