# Agent Note: Control history and isolated workers

Status: implemented

## Problem

The host filesystem and global session registry are shared by every plugin in a local harness. Browser identity checks alone cannot isolate user code, keep operator credentials private or make a restored metadata index safe after revocation and deletion.

## Decision

The control process owns identity authority, private history logs and a derived owner-scoped metadata index. Project storage reuses the existing JSONL/Zstandard provider and acknowledges saved history only after its fsync and the FULL SQLite index projection. Index reconstruction first checks the current journal-backed owner, then validates that the private log matches the owned workspace manifest; it never assigns ownership from cwd or a username. Readonly revision lookup comes from the physical persistence provider. Bulk metadata makes one real provider scan and revalidates every selected owner and workspace; index fields never issue source revisions or request authority.

Project HTTP admission reuses the existing `allowsProjectAccess` policy immediately after real request authentication and before URL, body or storage access. The internal assertion preserves the original denial class, code, status and message. Tests over detached principal facts cover the policy, including a USER with a required password change; they do not issue sealed request authority or claim that the native SQLite provider exposes such a public USER challenge. Ownership, CSRF, grants and revision checks remain in the actual carrier and providers. Admission also checks the active publisher barrier before accessing a provider or URL, so a retained authenticated callback cannot reenter a disposed HTTP plugin.

Worker content access uses the isolated runtime carrier, whose endpoint and credential reference belong to operator composition. Requests retain the existing ApiProxy format, reuse its browser-safe payload schema registry and recheck ownership/revision immediately before dispatch and publication; no endpoint selects the local host. Supervisor leases survive accepted background requests, and asynchronous revocation requires cancellation plus a process-tree quiescence receipt. An unverifiable receipt closes the adapter.

The worker persistence provider delegates to the native PersistenceCoordinator and borrows a lease-bound broker capability for owner-checked snapshots, append, raw pages and fork allocation. Cold hydration uses the operator-assigned volume; fork ids and lineage headers are registered in the control process before the worker receives them. RPC and SSE publication await the coordinator's durable flush. The worker's canonical Remote dispatcher is an operator-bound private callback, avoiding a Runtime–Connection–Gateway dependency cycle while preserving Typert codecs and named arguments. Approval and question responses require the original pending RPC id and active owner lease. An answer submitted by another valid login of the same USER remains linked to the originating lease through asynchronous authorization, final dispatch and receipt publication; expiration of that interaction refuses before allocating a replacement worker operation and does not log out the valid responder.

Grouping deletion changes presentation only. Session deletion commits an identity tombstone and awaits a separate ownership-deleted quiescence event before removing derived index rows; authentication cookies remain valid, and stale index restore cannot restore access. History readers reauthorize the session and its ancestors after physical I/O before returning data. Registered HTTP publishers check current ownership before headers, every chunk and after drain. Ancestor deletion blocks new publications, aborts affected channels and awaits their actual response close before ACK. The publisher barrier does not join private I/O queued behind the same storage exclusive, which would deadlock session deletion. Real filesystem isolation and backup purge remain deployment responsibilities.

A single identity-provider watchdog commits expired authentication sessions and awaits the session-expired event without new request traffic. Control cancellation and publisher barriers select the exact authentication session id and do not renew idle deadlines during passive checks. The operator supervisor determines physical cancellation granularity; control selection alone does not establish process or volume isolation.

History navigation uses bounded provider pages, with opaque session/revision cursors and UTF-8 boundaries. Uncompressed reads limit physical prefix I/O. A Zstandard page retains bounded output and validates the containing frame through its checksum before publication; a giant legacy frame requires extra streaming decode/I/O, while unrelated later frames are not decoded. Own raw exports preserve the original JSONL bytes and may include the owned volume's cwd; paths never supply ownership authority.

## Alternatives considered

A browser-local history store loses device-independent authority and restoration guarantees. Placing working trees in SQLite complicates normal filesystem tooling. Same-UID path validation cannot prevent an untrusted process from replacing a path ancestor or reading operator files; explicit worker isolation is required.

## Consequences

The operator deploys control and worker trust domains separately and verifies mounts, UID/process boundaries, supervisor credentials and egress before Internet activation. HTTP fixture receipts are narrower evidence than that deployment. A response close confirms the control carrier has ended, while bytes authorized before deletion may already be buffered by the kernel. The native supervisor fixture stops a workspace worker, so another login in the same workspace may require reconstruction; distinct-workspace SID selection does not prove fine physical isolation within one workspace. Existing event formats, replay, model routes, sandbox launchers and local profiles remain independent of the new carrier.
