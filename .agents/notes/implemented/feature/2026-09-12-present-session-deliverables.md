# Agent Note: Declare existing files as session deliverables

Status: implemented

English | [Português](2026-09-12-present-session-deliverables.pt-BR.md)

## Problem

The Web deliverables row recognizes successful filesystem mutation locations. Files generated by shell commands or external applications have no such mutation event, so merely mentioning a path cannot make them part of a turn's output list.

## Decision

The optional [tool-present plugin](../../../../packages/fs/tool-present/README.md) validates existing regular file references through the configured filesystem. It retains Session-relative paths and records the complete accepted list in `deliverables/presented`, attributed to the current turn and tool call. The [Web accumulator](../../../../packages/client/ui-deliverables/src/client/turn-deliverables.ts) combines explicit deliveries with mutation outputs in first-seen order and deduplicates exact paths. Its existing opener remains responsible for resolving the owning Session's paths.

The package adapts DeepSeek Harness tool-present at commit `c291e7961a515f6d7af9304e7fd1d257929aef26`; its [MIT notice](../../../../packages/fs/tool-present/LICENSE) remains with the source. The arx implementation reads the current turn from the existing event log rather than adding a projection solely for this consumer. Deployment configuration bounds the count and UTF-8 size of the complete retained metadata.

Publication occurs at `tools/result` after policy accepts the normalized result. The returned text confirms file validation, not delivery persistence. Registry containment logs an observer append failure without rewriting a settled result; a turn that closes before publication receives no late delivery.

## Alternatives considered

**Infer files from shell output or closing prose.** These texts can mention inputs, unrelated paths, or failed outputs and do not establish that a file exists. An explicit filesystem-validated declaration gives the UI a durable source.

**Append during execute.** The post-execute policy can still reject the tool result. Publishing there would leave a delivery for an operation that the final policy denied.

**Use content finalization as a throwing transaction.** The existing callback is documented as a total content transform, so changing its role for one consumer would weaken the tool contract. The final-success observer preserves registry semantics and the result states only what the tool can establish.

**Copy every file into an artifact store.** Immutable artifact storage is a separate capability with retention and access requirements. This packet retains current-file references and makes that limitation explicit.

## Consequences

Shell-generated outputs can appear in the same turn row and inline-reference opener as tool-written files. Existing mutation detection and old histories remain valid. Final-component symlinks, unavailable files, directories, and special entries reject the whole declaration, and cancellation or a stale turn cannot publish a partial list. Metadata bounds do not limit file content size or establish read-content permission beyond provider metadata checks.

Focused tool and invariant tests cover byte/count boundaries, provider failures, cancellation, post-execute rejection, publication failure, Session/fork attribution, and teardown. UI tests cover mixed outputs and replay. The keyless Loader application snapshot pins the model-visible validation result and recorded delivery from an externally created file.

The event is required rather than ignorable: the current event catalog restores it even when the present plugin is disabled, while older runtimes that lack the vocabulary refuse this newer log. No downgrade support is promised. The TypeScript and Python SDK subprocess tests preserve the complete event in both the returned event list and notification observer without changing final-response extraction.
