# Agent Note：打印运行中的版本号

Status: implemented

[English](2026-08-28-printing-the-running-version.md) | 中文

## 问题

侧边栏标出了产品名称，却从不说明是哪一个构建在提供页面。用户在两个检出之间比对行为、或提交缺陷报告时，没有任何可引用的信息。

`host.describe` 早已携带 `version` 字段，其值被硬编码为 `'0.0.1'`，旁边的 `TODO` 写着它应当读取 `apps/cli` 的清单。每一次握手都会把这个数字发给每一个客户端。没有任何地方渲染它，因此这个与任何发布都对不上的值，在无人读取期间一直无人察觉。

仓库同样有发布机制，却没有明确的节奏。`pnpm run release:arx` 可以递增并提交，但没有任何规定说明一次发布的修复对版本号负有什么义务，于是版本号是在有人想起时才变动，而不是在代码树变动时。

## 决定

应用版本是启动器事实，与 `provideCmdline` 已经提供的命令行和有界退出请求并列。`apps/cli` 在 `bin.ts` 中读取自身清单一次——它本来就为 `--version` 这样做——并把同一个字符串交给 `runProfile`，后者在任何树条目挂载之前将其作为 `ctx.appVersion` 提供。启动器之下的任何包都不需要读取清单来得知正在运行的是什么。

`host.describe` 按调用读取而非捕获，理由与 `requestExit` 按调用读取相同：启动器在树挂载之前提供它，而应答 `describe` 的闭包不应替任何它已经活得比其更久的世代发言。

`ApiProxyDefaults.appVersion` 是可选的，因为测试树不提供它，而线路字段并非可选。这一空缺在一个具名之处得到解决：`UNDECLARED_APP_VERSION`，其文档说明它代表无人发布过的代码树的版本。若改为让线路字段可选，同一个决定就会被推给每一个客户端，各自以不同方式渲染这一缺失。

外壳把它打印在字标下方。`.brandName` 变为列布局——先是它原有的字标行，然后是版本号——因此“logo 下方”是 DOM 顺序，而不是定位叠加。版本号读起来像一行说明：更小、次要、等宽字族，绝不与其上方的名称争夺注意力。

在重连间隙中该行不打印任何内容。当没有世代存活时，`hostDescription` 发布 `undefined`；外壳订阅该 source 而不是接收快照 prop，因此数字会随拥有它的那个世代一同离开。一个比其连接活得更久的陈旧版本号，会宣称运行中的应用是它并不是的那一个。

### 节奏

每一次发布的变更都要推进版本号，正是这一点让打印出的数字值得一读。每次变更或修复递增修订号；当实现者判断修订号不足以体现该次发布时递增次版本号；仅在仓库所有者提出时递增主版本号。[开发指南](../../../../docs/development.zh.md#version-cadence)是该规则的归属之处，`AGENTS.md` 链接到它。

## 备选方案

**客户端的构建期常量。** 品牌兜底已经读取 `process.env.ARX_CLIENT_COMMIT_HASH`，因此版本号本可以走同一条通道而不改动线路。已否决：那样命名的是*客户端产物*构建自哪个版本，而所提供的客户端与运行中的宿主是可以分别部署的。用户要问的是什么在提供这个页面。

**在网关内部读取 `apps/cli` 的清单。** 这正是 `TODO` 字面上提议的做法。已否决：`packages/host/apiproxy` 将不得不解析一条通往并非其依赖的应用的路径，并替一个它并不知道自己拥有的启动器作答。

**把 `UNDECLARED_APP_VERSION` 渲染为错误状态。** 没有启动器的树是一种真实的组合，而非故障。让外壳为此大声示警，等于为一个只有测试树和嵌入场景才会到达的条件，在产品中放置一条警告。

## 影响

`host.describe` 现在报告一个已发布的数字，因此任何读取它的地方——本外壳，以及日后加入的任何客户端——所指的都是一棵真实存在的代码树。它此前发送的 `0.0.1` 与仓库历史上的任何发布都对不上。

每个启动器都必须提供版本号：`provideCmdline` 把 `version` 作为必填字段，因此新的界面不可能在遗漏它的情况下抵达线路。唯一合理地没有启动器的组合，会在一个具名之处解析为 `UNDECLARED_APP_VERSION`。

两个会捕获品牌行的测试台各自固定了自己的版本号——侧边栏 DOM 快照中的 `9.9.9-bench`，Web scaffold 中的 `0.0.0-web-e2e`——因此版本递增绝不会改写基准文件。无论如何 Web 捕获也看不到它：品牌标识行是 `aria-hidden` 的。
