# Agent Note: ship, sync, integrate, then translate — the harness in executable order

Status: proposed

## Problem

Seven bodies of work are open on `rebrand/arx`, none of them a single change, and the order they are taken in decides whether the others can land at all. The numbers below were measured on 2026-09-04 and 2026-09-05 with the commands named beside them; re-measure before acting on them.

## Proposal

Eight phases, in this order and for these reasons: ship first, because nothing else lands otherwise; stabilize the two lanes CI judges, because every later phase pushes through them; write the upstream sync policy before translating anything the next sync rewrites; keep the corpus machinery to what the site needs and translate the site first; land integrations and the second subscription route through the sync policy so they arrive the way upstream work will; translate the rest last. Every commit follows [AGENTS.md](../../../../AGENTS.md): split independent changes, one Agent Note per non-trivial change, `--force-with-lease` never raw `--force`, nothing merged before checks pass.

### Read this before touching anything

Each line below is a trap that costs a turn; the executor can skip all of them.

- **Client bundle purity forbids runtime imports between browser plugins.** `packages/client/tsdown.client.ts` allows values only from the preloaded externals, the inline-safe wire layer (`INLINE_SAFE`: `arx-host-apiproxy`, `arx-file-reference`, `arx-session`, `arx-llm`, `arx-tools`, `arx-brand`), and generated `/remote` modules. A helper shared by two client plugins lives in one of those or is repeated inside a `/* jscpd:ignore-start -- <reason> */` block naming the gate. Only `pnpm run build` enforces this; `vitest` and `typecheck` do not.
- **The pairing gate has two modes.** `--cached <records>` (the pre-commit hook) checks only staged `.i18n.yaml` files; the corpus-wide check in `doc-sync` checks everything in scope. A pair whose Portuguese side links to a counterpart that does not exist fails both. Record a pair with `--write <english path>` only after both sides are final.
- **An Agent Note's language switcher sits on line 5.** Line 3 is `Status:`; `scripts/verify-agent-note-format.ts` and `scripts/archived-agent-notes.ts` pin it.
- **`scripts/rescope-vendor.ts` walks `git ls-files`.** A file deleted from disk but still tracked fails the gate with `ENOENT`; stage the deletion before `pnpm run hygiene`.
- **Generated regions are locked.** `docs/subsystems/*.md` carry `ts type-equiv` blocks matched against source JSDoc; `## Cordis API` regions come from `pnpm run gen-cordis-catalog`; `docs/config-catalog.md`, the graph documents, `packages/extensions/cordis-client-runner/src/client/slot-catalog.ts`, and `packages/extensions/tool-cordis/src/api-catalog.ts` are generated. Regenerate rather than edit; when no generator can produce the change a hand edit is recommended to the owner and made only once they authorize it. New seam types go in `LINK_MAP` and new event scopes in `EVENT_SCOPE_PAGE` of `scripts/gen-cordis-catalog.ts`.
- **Coverage is 100% per file under `packages/*/*/src`.** Measure with `npx vitest run --coverage --coverage.include='<package>/src/**' --coverage.reporter=text <package>`; an unreachable guard is a coverage hole, so restructure rather than exempt.
- **Measure against the baseline, not zero, until Phase 0 lands.** Compare failure sets against `HEAD` with the change stashed: `pnpm run lint` at 11 errors, `pnpm run test` at 16 failures, `verify-md-links` at 27. A count that matches can hide a swapped failure; diff the sorted lists.
- **Count Chinese with a Unicode-aware tool.** `git grep -E '[一-龥]'` miscounts by bytes; a Python `re.compile(r'[一-鿿]')` over the file tree gives the 24/24 above.
- **Workflows die at the session limit** and resume from `resumeFromRunId` with completed agents cached. Keep batches small and commit per verified batch. A multi-agent workflow runs only when the session's user asks for one; Phase 7 assumes that request.

### Skills the executor loads

Each rule below binds every phase; the per-phase `Skills:` lines name the step where a skill applies.

- **Before every push — [arx-pre-push-checks](../../../skills/arx-pre-push-checks/SKILL.md).** `pnpm --silent run change-scope --base <live PR base or stack parent>` selects the evidence; each selected check runs once per outgoing diff; typecheck belongs to the pre-push hook and is never rerun by hand; a rewritten branch pushes with `--force-with-lease=<branch>:<OID from a fresh fetch>` and re-audits review threads and mergeability afterwards; a selected check that fails on the change blocks the push, and no hook is bypassed without the user's agreement. Phase 0's full coverage and lint runs are the skill's CI-diagnosis clause.
- **Before every merge — [arx-code-review](../../../skills/arx-code-review/SKILL.md).** Verify the live base and exact head; review changed prose under the prose standard; every new or ported plugin registration carries the disposal tests `packages/AGENTS.md` requires; README and JSDoc change in the same diff as the behavior; a core import updates `docs/subsystems/*.md` and its `type-equiv` entries.
- **On every diff's prose — [arx-prose-standard](../../../skills/arx-prose-standard/SKILL.md) and [arx-trim-cot-leakage](../../../skills/arx-trim-cot-leakage/SKILL.md)**, with the scope named as the phase's file globs and never corpus-wide; `vendor/`, `.agents/notes/archived/`, and recorded goldens and fixtures are excluded; an imported upstream document qualifies its citations as `deepseek-harness PR #N` and keeps `PR #N` inside Agent Notes; findings are reported, edits applied only on an explicit fix request, and no phase sets a word-reduction target.
- **On every Agent Note — [arx-archive-agent-notes](../../../skills/arx-archive-agent-notes/SKILL.md).** A new or imported note runs the supersession audit against active notes in the same PR: a fully superseded implemented note is archived by the triplet procedure (move `.md`, `.pt-BR.md`, and `.i18n.yaml` to `archived/<kind>/`, add only the identical `Archived: YYYY-MM-DD` line below the status line on both sides, re-record the sidecar, repair inbound links, seal with `pnpm run verify-archived-agent-notes --write`), a partial supersession is cross-linked, and a rejected note the decision makes obsolete is deleted; a PR that archives or deletes adds that gate to its proof. A proposed note is never archived: when a phase completes, this note moves to `implemented/` with its Proposal as the Decision and its Acceptance criteria and Risks folded into Consequences, or is rejected with the reason on its status line.
- **On every documentation change — [arx-doc-standards](../../../skills/arx-doc-standards/SKILL.md) and [arx-doc-site-sync](../../../skills/arx-doc-site-sync/SKILL.md).** `pnpm run doc-sync`, `pnpm run lint`, and `git diff --check` before push; a touched pair is re-recorded with `--write <pair>` and checked with `npx tsx scripts/verify-translation-pairing.ts <pair>` for exactly those pairs; a Portuguese page is the sibling `<name>.pt-BR.md` of its source in `docs/`, never a tree under `website/`; links stay repository-relative; an import or a widened `included` never adds a `website/docs.ts` entry; a green `website:build` ends the site work, with no Pages deployment unless the owner asks. The sync manifest lives outside `included`.
- **On every deferred cleanup — [arx-find-simplifications](../../../skills/arx-find-simplifications/SKILL.md).** A cleanup deferred in a phase is a `TODO(<smell>)` inline note naming the safe action, or a backlog line here when it is a decision; an import that fully supersedes a local note consolidates that note's rationale, alternatives, and verification into the imported owner.

### Checkpoints: model, effort, and the stop

Phases do not want one model or one effort level: one decides what enters the core, several are diagnosis, several are mechanical. At each checkpoint the executor **stops before running the phase's first command** and ends its turn with this line, in the language the user writes in — for this repository's owner, Portuguese:

`PARADA <n> — ajuste o modelo para <model> e o esforço para <level> e responda "continuar".`

It runs nothing from that phase until the reply arrives. A checkpoint reached with the model and effort already at the named values still stops: the stop is also where the user reads the previous phase's proof before paying for the next. Checkpoints govern the executor's own session; agents inside a workflow take the `model` and `effort` options their script gives them, and the table names those too. `xhigh` sits between `high` and `max` and is the level for coding and diagnosis on the current models; the ladder uses it where diagnosis or conversion is the work and reserves `max` for the one contract decision.

| Checkpoint | Before | Model | Effort | Why this level |
|---|---|---|---|---|
| 0 | Phase 0 | `claude-opus-5` | `xhigh` | Six distinct failures across four runtimes; diagnosis, not the mechanical release its step count suggests. |
| 1 | Phase 1 | `claude-opus-5` | `xhigh` | Converting 24 tests and reading 24 golden diffs, plus a Windows lane whose failures are timing and encoding; a wrong conversion becomes the new truth when re-recorded. |
| 2 | Phase 2 | `claude-opus-5` | `max` | The one phase that decides what enters the core; a wrong rule propagates through every later sync. |
| 3 | Phase 3 | `claude-opus-5` | `high` | Scripts with specs and one re-sync; the design is settled. |
| 4 | Phase 4 | `claude-opus-5` | `high` | Sixteen files read closely against the terminology table — the first real test of it. |
| 5 | Phase 5 | `claude-opus-5` | `high` | Configuration and one ported package; the Google Ads spike is the only judgment. |
| 6 | Phase 6 | `claude-opus-5` | `xhigh` | A second vendor's protocol, read against four properties; the spike decides whether the phase builds anything. |
| 7 | Phase 7 | Verifiers `claude-opus-5`; translators `claude-opus-5` until the phase's own measurement admits `claude-sonnet-5` | `high` for the session; in workflow scripts, `effort: 'high'` for translators and verifiers, `'medium'` for link-flip and regeneration agents | Fidelity of meaning is the one thing no gate checks; the mechanical agents need none of it. |

Between checkpoints the model and level stay where the last one set them. A phase that is skipped or reordered keeps its own checkpoint.

### Phase 2 — the upstream sync policy

Model `claude-opus-5`, effort `max` — checkpoint 2.

Skills: arx-merging-stacked-prs for every stacked sync group; arx-archive-agent-notes on every imported note; arx-trim-cot-leakage and arx-doc-standards on every imported document; arx-find-simplifications where an import supersedes a local note; skill-creator when `ci-test-reliability-skill` lands as `arx-ci-test-reliability`; arx-pre-push-checks after every `gh stack sync`.

The harness is a fork with no procedure for taking upstream work, and the core changes upstream is making are the ones this repository must judge rather than absorb. This phase writes the procedure, the rule, and the first triage, and executes one sync through them. Record it as a process Agent Note; the manifest lives in `docs/upstream-sync.md` unless [docs/AGENTS.md](../../../../docs/AGENTS.md) places it elsewhere.

**2a. The procedure.** Model it on the [vendored-package sync procedure](../../../../vendor/README.md): a manifest naming the upstream repository, the last-synced upstream commit, and the last-triaged Agent Note date; a keep-list of paths sync never overwrites; a drop-list of upstream paths sync never imports; and the unit of import — one upstream Agent Note with the PR that implemented it, cherry-picked and re-scoped, never a merge of upstream `master`. Each imported decision lands with its Agent Note carried over as the English side (switcher-less until its Portuguese side exists) and its documents entering the corpus under the `included` rule from Phase 0. The procedure document states its prerequisites (the upstream remote and the last-synced commit), the exact commands for one decision import, and its verification (`verify-agent-note-format`, `--list`). An imported document has every relative link rewritten to a path that exists here — dropped packages, `.zh.md` sides, and `dsh-*` names repaired or removed — and its upstream PR citations qualified as `deepseek-harness PR #N`; importing never adds a `website/docs.ts` entry.

**2b. The core rule.** A change to `packages/core/*`, `packages/session/session-persistence*`, the agent loop, or `SessionEventMap` is imported only when it removes a failure class this repository has, or when another imported change requires it; never when it removes a capability this repository ships without a migration path. Each such import gets its own Agent Note stating which clause admitted it. Under this rule `released-session-format-migrations` is a candidate — a `SESSION_FORMAT_VERSION` bump refuses older logs, and a migration chain removes that failure class — and `jsonl-only-session-persistence` is not, because the SQLite store ships and the note offers no migration.

**2c. The lists.** Keep: `packages/llm/llm-agent-cli`, the `llm-pi-ai` presets, `packages/examples/`, `examples/`, `host/apiproxy`, `session/session-persistence-sqlite`, `subagent/subagent-arx-sdk`, `subagent/tool-subagent-report`, `subagent/claude-agent-sdk-process`, `client/ui-settings-web`, `client/ui-exit`, `client/runtime`, `test-support/acp-snapshot`, the brand (name, wordmark, favicon, design tokens), and `docs/i18n/*`. ## Alternatives considered

- **Translate the whole corpus first, documentation site first, before any upstream sync.** Honors the link rule and the chosen site-first order, but every later sync arrives with English documents whose Portuguese sides do not exist and reopens the pairing gate over documents already translated; upstream's removal of the SQLite store shows a document translated in a wave can be rewritten or deleted by the sync after it. The site stays first; the rest waits for the policy.
- **Merge upstream `master` into `rebrand/arx`.** The rebrand rewrote identifiers, file names, and a design-token ramp, and retired the vendor's packages; a merge re-imports the vendor as a brand, the Chinese corpus, and the packages on the drop-list, and overwrites the 63 decisions upstream lacks. Per-decision import under a keep-list is the only shape that keeps them.
- **Never sync.** Seventy decisions in ten days include fixes to code this repository ships — `code-runtime-python`, the Windows lane, workspace paths — and a session-format migration chain it lacks.
- **Keep the nine-phase corpus plan and append sync, integrations, and Windows as new phases.** Its Phase 0 could not close: knip, duplication, and lint block required checks and sat in its Phase 8, so the ordering was inverted for the gates that decide shipping.
- **`claude-fable-5-1` for Phase 2.** The most capable model for the one phase whose error propagates into the core, at twice the per-token price of `claude-opus-5`; the ladder already reserves `max` for that phase. Reconsider if the first sync's triage proves wrong in a way effort did not catch.
- **A second subscription route in the backlog.** The premise treats multi-vendor subscription access as foundational and it is false for OpenAI; the spike bounds the cost to reading a protocol against four properties.
- **Google Ads as an in-tree Cordis plugin.** Hand-rolls an OAuth2 and GAQL client against the dependencies policy; the authorization flow is the only part the harness must own.
- **A migration flag that tolerates missing counterparts everywhere.** Simpler than `included`, but it makes the gate lie for the whole migration instead of telling the truth about a declared scope.
- **Excluding generated documents from pairing permanently.** Removes the generator work but leaves the Portuguese site without its catalogs and API pages.
- **Translating archived notes.** Out of scope by the manifest and frozen by the archive gate; the 143 legacy `.zh.md` files stay as they are.

## Risks

- **Upstream outruns the triage.** Seven decisions a day means the manifest's last-synced commit ages while a sync is in flight; every sync begins by re-listing, and a sync that takes longer than a week is split rather than widened.
- **The core rule is misapplied.** A change admitted under "removes a failure class" that also removes a capability ships a regression into the session log; the Agent Note per core import names the clause and the capability check, and Phase 2 runs at `max` for this reason.
- **The keep-list rots.** Upstream renames or splits a package the keep-list names by path; the manifest keys the keep-list by package name and path both, and a sync that touches a keep-list name stops.
- **Terminology drift across a thousand files** is the quiet failure; the gate in Phase 3 and the batch verifier are the mitigation. Do not start Phase 7 without both.
- **Link flips touch already-recorded pairs**; every flip re-records them, so a flip that lands wrong looks consistent. Review the flip diff, not only the gate.
- **The second subscription route pays the same cost as the first**: every step re-sends the transcript and spends quota re-reading it; the spike states this cost before building.
- **A webhook without TLS** is an ingress a proxy must front; the ported README says so and the default composition does not mount it.
- **Google Ads developer-token approval** is an external dependency with its own timeline; the spike records it as the trigger, not the phase.
- **Session limits interrupt workflows**; committing after every verified batch is the only checkpoint that survives.
- **The e2e goldens are re-recorded wholesale in Phase 1**; a conversion mistake becomes the new truth unless every diff is read.
- **Cost**: the corpus is roughly a million words of output plus review; budget it per wave and stop between waves, never mid-batch. The Phase 7 measurement exists so the cheaper model is adopted on evidence, not on price.
