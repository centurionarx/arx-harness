# Agent Note: Native application composition shares the slot engine and owns a fresh boot lifetime

Status: proposed

## Problem

The legacy browser boot preloads runtime, creates project services, and renders a session-aware root before presenting the page. Login and administrative pages need neither a project nor a conversation. Hiding project widgets leaves those factories, connections, global configuration injections, persistence keys, and delayed callbacks alive. A MASTER_ADMIN must never receive owner content, and a revoked USER tree must stop publishing its previous owner's state.

## Proposal

Move the existing SlotRegistry and framework snapshot-store engine into the neutral client-slots provider. Runtime reexports their existing faces for compatibility. Preserve one slots.register API, one registry, one renderer, and the four derived props shares. An application registration uses PropsApplication derived from the same SlotMap authority and omits project/session standard hooks; project remains the default and retains the original contract. Reject project entries, project child scopes, and project render hooks in application trees rather than inventing sessions or workspaces.

Every Cordis-backed registration stamps an explicit registrant or the current Fiber name. The vendored [Fiber name getter](../../../../vendor/cordis/src/fiber.ts) returns the nearest named ancestor or `root`, so a genuine Context never needs an absent-name fallback. The framework keeps the core registrant field optional for callers outside this provider and retains registration identity and disposal guards. The injection controller receives its actual declaration unsubscribe before reconciliation: [SlotCore.subscribeDeclaration](../../../../packages/client/ui-slots/src/index.ts) only creates the record, adds a listener, and returns its remover synchronously; it does not invoke callbacks during subscription. The controller therefore has no placeholder unsubscribe, while stop, epoch, renderer/locale identity, and registration disposal checks remain in place. Genuine root, unnamed descendant, named ancestor, and explicit-registrant cases pin the stamp; disposing an old registration twice must preserve its replacement.

Select public, admin, and USER-without-runtime as application compositions; select an ACTIVE USER with the runtime grant as a project composition. This internal scope is derived from the validated server session. The HTML marker contains only kind, audience, and optional generation and is a consistency view. The serving audience comes from deployment configuration and a real auth/session response. A mismatched or stale marker closes the boot before materialization, and public/admin never import connection or project runtime.

Keep the existing locale/theme project plugin exports and inject assertions intact. Each same bundle exposes a closed application face that shares its presentation service and apply implementation while omitting eager project preferences. The kernel selects only these declared faces; factories and value exports keep one cache within one boot. USER transition requires a new module system and Context, so a public application's cached exports cannot become a project session. Move the pure DOM theme presenter into the theme foundation and retain its layout reexport. This is the approved presentation-only exception to the normal cross-plugin value-face rule, not a new business helper API.

Native HTML uses the request-aware WebServer renderer registration, authenticates the original request, projects an explicit closed graph, and revalidates the session before returning HTML. It emits no shared operator configuration, principal, CSRF verifier, or global index tap. The neutral graph has six required packages. The project graph has a closed base and only installed members of the reviewed runtime feature roster; unknown dependency closure fails. Native remotes mount only commands, goals, own references, feedback, turn outlines, and file previews. Operator dynamic packages, inventories, projects, repositories, GitHub configuration, and global settings remain unavailable in this profile until a separately scoped interface exists.

The first native inline script captures and removes a recovery fragment before any bundle loads, transferring it only through a one-use callback handle backed by a private closure. AuthClient takes and clears that handle before auth/session; failure, unmount, and pagehide discard it. The browser reads auth/session before ModuleLoader.create, prefetch, or plugin factories. Cookie-only authentication keeps CSRF and recovery fragments in private tree memory; recovery fragments are removed before factory or telemetry execution. Auth-only invalidation, HTTP 401, expiry, logout, restoration, or an unavailable identity service unmount the root, cancel requests and response-body reads, abort script arrival and late factories, dispose the Context, and wipe principal state, selections, history state, arx view caches, and pending callbacks. Cross-tab notices carry only a neutral invalidation signal. Native framework stores never persist project or conversation content in browser storage.

A native document originally served at `/reset` or `/invite` also owns early capture-phase hashchange and recognized-recovery popstate listeners. They read only the current hash, remove it synchronously, suppress URL-bearing downstream delivery, clear by handle identity, and publish a neutral signal. Pagehide releases both listeners. This guarantees the current URL before taps, not removal of non-current history entries; Back may capture an old entry as a new navigation. Other documents and popstate events without a recognized recovery hash preserve their navigation semantics.

Bootstrap installs its observer before the first session GET; constructors do not capture fragments. Each capture advances an epoch, cancels old requests/polls, discards old capabilities and remounts the form by a neutral revision. The actual auth service supplies a delegated readonly AuthView observable: only a new recovery-checking revision delivers its listener through ReactDOM flushSync, from the external publisher callback, before revalidation starts. Normal notifications retain their scheduling. A private kernel callback checks the original canonical pathname and the verified marker/manifest. The refreshed session must retain authenticated state, audience, user id, generation, and private CSRF; otherwise the tree closes. All awaited bodies and late form callbacks check the epoch, and a reset/invitation POST takes its capability synchronously once. A matching recovery reuses the existing public module system; changing principal/composition still requires a fresh boot. Raw V8 execution of the exact inline string is recorded separately and is never mapped to TypeScript literal counters.

Logout begins by retracting every private tree before waiting for HTTP. The same origin-local BroadcastChannel is handed to a kernel-owned completion containing only operation state, id, and the persistence result; it retains no auth client, Context, principal, or CSRF value. A `logout-ack` follows only the real successful logout POST. Matching acknowledgement is a navigation hint: fresh HTML and auth/session must still agree before factories. Pagehide, kernel teardown, late callbacks, duplicate acknowledgements, and channel disposal never remount old exports. A failed POST leaves both views neutral without heuristic retries.

The browser stores one negative guard with only origin, audience, generation, and a neutral operation id. This is denial metadata, never authority or a backend identity. The kernel consults it after real session, marker, and manifest verification and before private imports/factories. Anonymous server state, a genuinely different validated generation, exact active acknowledgement, or explicit server-confirmed login may clear it. Compare-and-remove uses the exact operation id so an old acknowledgement cannot erase a later same-generation denial. Explicit login also handles generation collisions between users without adopting any other user's snapshot. The existing request-rendered public recovery path supplies login while private admission stays closed. Refused or malformed storage fails closed for private composition, and the neutral page explains the limit on cross-document persistence when browser storage is unavailable. Private cache purge preserves this denial-only record. The slot-store purger reserves the exact `arx.web.logout-denial` key; every other private view key remains purgeable. Auth end disposes its bootstrap listeners and private state before the kernel aborts the tree, preventing a reentrant pagehide boundary from closing the neutral completion. Each subscriber failure is contained and the boundary runs through finally. Logout owns both synchronous boundary failures and the detached real HTTP promise, disposing its completion and containing a late rejected request without waiting or retrying.

The USER authentication module presents virtual own project/workspace names and server history through the canonical project-storage HTTP contract. It never asks a browser-local folder picker for a VM path. A no-runtime USER keeps account, logout, and own storage navigation through the application root; resume, fork, and workspace execution require actual project services. A project USER has an account footer/dialog owned by the same module, independent of the operator Settings shell. The default history projection omits the technical session header while explicit owner-only exports preserve original bytes and can include paths from that owner's volume. Grouping removal, conversation deletion, and file retention remain distinct operations.

HTML preview retains the production sanitizer, restrictive CSP, and an opaque iframe sandbox without allow-same-origin or scripts. Native previews exclude the desktop-open action. There is no generic worker postMessage tunnel or shell-credential bridge in the preview component.

This partially extends the [slot type-chain decision](../../implemented/architecture/2026-07-22-slot-type-chain-implementation.md), [web session scope and provide channel](../../implemented/architecture/2026-07-25-web-client-session-scope-and-provide-channel.md), [locale/theme preferences](../../implemented/architecture/2026-07-25-client-settings-locale-theme.md), and [client plugin loading model](../../implemented/architecture/2026-07-23-client-plugin-loading-model.md). Their independent local project, four-share, lifecycle, preference, and lazy-module rationale remains active. The ownership changes above require a later complete supersession audit, so this proposal does not archive or remove those records. The [native control-plane proposal](2026-10-08-native-web-authority-and-owned-control-plane.md) owns server authority, durability, and operational isolation.

## Alternatives considered

A login overlay keeps project boot and host connections alive. Dummy project services add a permissive authority substitute. A second slots/context/hooks API duplicates render authority and typing. Reusing a module system across principals retains old closures. A global native index injector cannot project current request identity. Falling back to a local profile on HTTP 401 or unavailable workers reaches an operator runtime. Opening global settings or operator remotes to make the UI appear complete breaks the administrative/content boundary.

## Acceptance criteria

Keep legacy injection assertions, goldens, replay consumption, sandbox limits, and existing timeouts. Validate application props against the genuine shared SlotMap, prove single factory/registry ownership and late-factory cancellation, and check the closed graph against actual package declarations. Source fixtures must authenticate through real Loader, HTTP, SQLite, journal, and owner storage; only external delivery and model providers may be replaced. Built-browser gates must use actual request-rendered HTML, static bundles, two USER accounts, MASTER administration, owner denial, session/event isolation, logout/back/restore/multi-tab cleanup, accessible responsive views, and malicious opaque previews. A private temporary package-resolution symlink catalog is a fixture composition receipt, not an installed-package acceptance result.

## Risks

An HTTP or subprocess fixture cannot prove independent VM worker UIDs, mounts, or network policy. Static JavaScript source is not private configuration, so graph/config projection and backend authorization remain separate checks. Session/header raw exports deliberately preserve owner artifact bytes. A missing runtime grant is supported through application storage navigation; a missing configured worker leaves execution unavailable. Quotas, retention, deletion policy, delivery, HTTPS publication, deployment, and Git synchronization require their own approved operational work. This note remains proposed until the integrated type, browser, package, benchmark, and independent-review gates are complete.
