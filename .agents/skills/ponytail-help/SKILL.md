## arx Harness integration

These are model-independent instructions, not a Claude Code plugin. Use the arx `skill` tool or explicit `/ponytail-help` invocation; do not run marketplace installers, hooks, auto-updaters, or write mode flags. Availability requires the session to expose the `skill` tool. Follow the repository instructions, requested scope, approval policy, security requirements, documentation obligations, and existing test framework. Never remove required validation or tests to reduce line count. Guidance remains ordinary logged context until compaction; no automatic activation, durable intensity setting, or child-context propagation is installed. For other capabilities, keep consulting the existing skills-globais catalog.

# Ponytail Help

| Skill | Purpose |
|---|---|
| ponytail | Reuse existing code, standard libraries, and platform features before adding code. |
| ponytail-review | Review a diff for unnecessary complexity; apply nothing. |
| ponytail-audit | Audit a requested repository scope for complexity; apply nothing. |
| ponytail-debt | Report explicit `ponytail:` deferral comments. |
| ponytail-gain | Explain upstream benchmark evidence and limits. |
| ponytail-help | Show this reference. |

Invoke `/ponytail`, `/ponytail-review`, or another exact skill name, or ask the agent to load that skill. Request lite (suggest alternatives), full (prefer the smallest valid implementation), or ultra (challenge speculative additions) in ordinary task text. Explicit user requirements and repository checks remain mandatory at every intensity. Say "stop ponytail" or "normal mode" to end the guidance.

All configured model routes can access these skills when the session exposes the arx `skill` tool; no Claude account or native plugin installer is required. The minimal preset does not expose that tool. There is no automatic session mode, environment-variable mode selector, status line, or automatic update. Compaction or an independent child can require another skill load. Updates are reviewed source changes pinned in the integration provenance, not `/plugin` commands. This help changes no configuration.
