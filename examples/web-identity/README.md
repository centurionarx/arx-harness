# Native web identity keyless fixture

This reference owns [cordis.yml](cordis.yml) and [tests/harness.ts](tests/harness.ts), which boot the real Loader, protected journal and separate identity SQLite provider with private synthetic paths, random fixture passwords/keys and a fake external mail-acceptance provider. Optional HTTP wiring uses an explicit insecure-loopback fixture flag. The default composition mounts no base/web-app/session/agent/tool service; extra consumers are composed explicitly.

The helper returns real MASTER and requested ready USER authorities, captured delivery messages and private paths for storage/runtime packages to compose their real consumers. `readyUsers` establishes each recipient's synthetic password before administrative release; `delivery: false` suppresses external replacement registration. The fixture explicitly chooses an eight-hour absolute session budget and thirty-minute idle budget; TTL/rate overrides are bounded and distinct from deployment policies. The required provider idle policy has no production default. Clock-controlled expiry tests retain real Loader, SQLite, journal and HTTP operations and verify passive polling, request-fence denial, absolute capping and durable activity after reopen. `accessMode`, `packageBaseUrl` and `extraPlugins` provide the actual client/host composition entry without an auth mock.

Package-owned tests compose this helper, including [the identity contract tests](../../packages/identity/web-identity/tests/contract.spec.ts). The protected runner supplies private ARX_HOME, absent CXH_HOME and the original process/filesystem root-dotenv guard. Low-level failure fixtures delegate native hashing/SQLite/IO and inject only named boundary faults. Synthetic credentials remain in private temp storage or process memory; the browser host passes them through IPC.

In the Vitest `thread-safe` project, [tests/identity-seed.global.ts](tests/identity-seed.global.ts) bootstraps one USER identity per run in the background, and a USER start of the HTTP browser fixture copies that root instead of hashing the MASTER and user passwords again. The seed reaches each start through a loopback server that requires a per-run token, and credentials travel only over loopback and private IPC. Each start reports its module-load and harness time on stderr ([rationale](../../.agents/notes/implemented/testing/2026-11-24-http-browser-fixture-copies-a-per-run-identity-seed.md)).

SQLite-native backups remain in private 0700 directories and are 0600 before restore. Keep the authority journal and private keys outside the restored DB/log/volume set. The fixture proves current-revision/tombstone/token denial over older synthetic snapshots; it does not restore operator infrastructure.

[The identity decision](../../.agents/notes/implemented/architecture/2026-10-08-native-web-identity-journal-and-audience.md) owns authentication and ACK rationale; [the storage/runtime decision](../../.agents/notes/implemented/architecture/2026-10-08-control-history-and-isolated-workers.md) owns content/index and remote execution. The [deployment proposal](../../.agents/notes/proposed/architecture/2026-10-08-native-web-authority-and-owned-control-plane.md) keeps a new control VM and independently isolated workers separate from fixture evidence. Existing Landlock allows broad reads, and E2B does not relocate the entire harness. Production quotas/retention/backup RPO/RTO and real delivery require operational approval and measured evidence. This fixture authorizes no Git, real account, credential, email, service, DNS or infrastructure action.
